# FeishuZhCmd（飞书中文命令）v1.0

MoviePilot 插件：把**飞书机器人自定义菜单**发出的中文文本翻译成 MP 标准命令并执行，
菜单名保持简洁中文（飞书后台「机器人自定义菜单」的「发送文字消息」需设置与中文名称保持一致）。

## 解决什么问题

飞书「机器人自定义菜单」的「发送文字消息」动作，发出的是**菜单名称本身**（没有单独的文字输入框）。
而 MP 只认以 `/` 开头的命令。更关键的是：MP v3.2.2 消息链的 `resolve_media_action`
会把 2~10 字的纯中文（如「正在下载」「订阅列表」）**判为影视标题、当成「搜索片名」提前消费**，
消息根本到不了任何插件可监听的事件 —— 这就是点按中文菜单后 MP 按该文字搜索资源
（而不是执行命令）的原因。

**核心机制（渠道挂接）**：插件在运行时找到 MP 的飞书渠道实例，在它的入站消息入口
（`_on_message`）之前挂一层拦截。中文菜单名命中「中文菜单名 → 命令」映射表、且用户通过
管理员白名单校验时，插件直接以原生方式触发 `EventType.CommandExcute` 执行命令，
并**拦截该消息**（不转发给消息链），MP 永远不会把它当影视标题搜索。
**未命中的消息一律放行**，不影响「订阅 / 搜索 / 洗版 + 片名」等 MP 原生自然语言交互。

插件同时保留 `UserMessage` 事件监听作兜底：在渠道挂接失效的窗口内，能被消息链放行的
中文文本仍可翻译。

## 安装

1. 从 GitHub 仓库安装：MP 插件市场 → 仓库 `SixOrg/MoviePilot-Plugins` → 找到
   `飞书中文命令` → 安装；或把 `plugins.v2/feishuzhcmd/` 目录放入本地插件仓库后刷新市场；
2. MP 后台 → 插件 → 启用 `飞书中文命令`；
3. 在插件配置页确认「启用插件」已打开，映射表按你的实际菜单名核对（默认已按推荐分组方案填好）；
4. 飞书后台保持一致性：菜单名保持现有中文或自定义，但必须与映射表左边一致。

## 配置说明

插件配置页包含两个项目：

1. **启用插件**开关：关闭后中文菜单文本不翻译、直接放行；
2. **中文菜单映射表**：一块多行编辑器，**默认已列出全部 16 条推荐映射**（每行一条 `菜单名=命令`），
   你可以直接增删改任意行，保存后生效。

格式要求：
- 每行一条：`菜单名=命令`（命令为完整命令文本，含 `/` 和参数，必须是 MP 已注册命令）；
- `#` 开头的行为注释，不生效；
- 清空映射表后保存，会自动恢复默认内置的 16 条映射（防止误删导致插件失效）；
- 映射表保存后立即生效，无需重启；未命中映射的消息会放行给 MP 原生逻辑，不会产生副作用。

## 安全说明

中文文本消息**不会经过** MP 渠道层对 `/` 命令的管理员校验，因此插件自带白名单：
- 白名单来源：优先读取「通知 → 飞书渠道」渠道配置里的 `FEISHU_ADMINS`（管理员，
  逗号分隔）与 `FEISHU_OPEN_ID`（默认接收用户）——即你在 MP 后台表单里填的值；
  读不到渠道配置时回退全局同名环境配置；
- 触发命令的用户命中任一即放行；两者都未配置时插件**不会执行任何命令**
  （保守默认，防止任意用户触发系统命令）。

## 兼容性与失效恢复

- 基于 MoviePilot v3.2.x 插件 SDK（`app.plugins._PluginBase`）开发；
- 渠道挂接依赖 MP 内部结构（模块管理器与飞书渠道实例），MP 升级或渠道实例重建后
  挂接可能失效；插件每 60 秒自动校验并补挂，并保留 UserMessage 事件兜底；
- 若点菜单仍无效，看 MP 日志：
  - 无 `feishuzhcmd: 已挂接飞书渠道实例` → 插件页停用再启用一次（立即重挂）；
  - 有 `feishuzhcmd: 飞书文本未命中映射：<文本>` → 日志会打印实际收到的文本，对照映射表左边改；
  - 有 `feishuzhcmd: 用户不在白名单` → 确认 MP 通知渠道里「默认用户 Open ID」/「管理员白名单」
    已填且与你点菜单的账号一致；
  - 有 `feishuzhcmd: 飞书菜单「xx」映射为命令` → 已触发，问题在命令本身；
- 停用/卸载插件即还原挂接并恢复原生行为。
